# Work Log — 2026-08-30

## Investigated the MERID-001 billing total discrepancy

Root cause (verified in `data/billing.csv`)

The `billing_summary` task's current instructions just ask the agent to
"summarize total invoiced vs total paid" from the raw event log. The event
log is not a clean ledger — each logical invoice can appear as *more than one*
`invoice_issued` row, and credits can appear in up to three places. Summing
`amount` naively over all rows inflates the total. Concretely:

- **Duplicate issuance, different amounts**: `INV-2025-MH-022` has two
  `invoice_issued` rows — `BIL-5105` (€18,583.58) and `BIL-5160` (€18,853.58,
  "reissued at James Park's request" because the original wasn't visible in
  Meridian's AP portal). Only one payment was ever received (€18,583.58,
  matching the *first* row). Summing both rows overstates invoiced-but-unpaid
  by €18,853.58 for one real invoice.
- **Credit counted redundantly**: SLA credit `CN-2025-MH-002` (€929.18) shows
  up as (a) a `credit_note_issued` row, (b) netted directly into
  `INV-2026-MH-027`'s issued amount (€17,654.40 = €18,583.58 − €929.18), and
  (c) a separate `credit_applied` row. Naively summing every row subtracts
  the same €929.18 up to three times.
- **Undocumented ad-hoc discount**: `BIL-5228` is a −€1,854.00 `adjustment` on
  `INV-2026-MH-027`, "agreed verbally with James Park during renewal prep. No
  credit note issued yet." Payments received against that invoice
  (€17,654.40) match the amount *before* this adjustment — so it's a
  commitment that hasn't actually been collected or credited anywhere yet.
  Worth surfacing to the account manager explicitly rather than silently
  netting it into any total.

Other messy-looking events that are actually fine and shouldn't be flagged as
anomalies: the duplicate *payment* on `INV-2024-MH-006` (correctly refunded,
nets to zero), the €847.50 unmatched payment (correctly returned), the 1-cent
rounding adjustment on `INV-2024-MH-005`, and the AP-side split payments
across Engineering/Marketing on invoices 021/026/027 (sum to the invoice
total).

## Implementing the solution

### Step 1 — reconciliation pass (`src/challenge/tools/billing_reconciler.py`)

Added `reconcile_billing(account_id)` — canonicalizes `invoice_issued` rows to
one per real invoice_id (matching against payment received when an invoice
was reissued, else most recent issuance), sums only `INV-`-prefixed
`payment_received`/`refund_completed` rows for total paid, and treats
`credit_note_issued`/`credit_applied` rows as informational (never summed —
the credit is already netted into the invoice's amount) plus material
(`>= €1`) `adjustment` rows as call-outs. Wrapped it as
`BillingReconciliationTool` (`reconcile_billing` tool name) and registered it
in `tools/__init__.py`.

Ran it directly against `data/billing.csv` for MERID-001 to validate before
wiring anything else in:

```
invoice_count: 28
total_invoiced: 509852.11
total_paid: 454101.37
outstanding_balance: 55750.74
anomalies: [reissued INV-2025-MH-022 (used the amount matching the payment),
            2 credit notes (informational, already netted),
            the €1,854 undocumented verbal adjustment (excluded from totals)]
```

Numbers match hand reconciliation from the earlier investigation.

Registered `BillingReconciliationTool` in `tools/__init__.py` alongside the
existing tools. Not yet wired into any task/agent — that's the next step,
to be tackled on its own.

### Step 2 — wire the tool into the `billing_summary` task

`runner.py`: `run_task` now passes `task_def.get("tools")` through to
`ActorAgent`, so a task can opt into extra tools beyond the default CSV
reader / PDF report pair. `usage_trends` and `support_health` don't set
`tools`, so this is a no-op for them. `tasks.py`: `billing_summary` now gets
`tools: [BillingReconciliationTool()]`.

Verified: imported `TASKS` directly and confirmed `billing_summary` carries
the tool instance while the other two tasks still have `tools: None`.

### Step 3 — update the `billing_summary` prompt

Rewrote the task prompt (`tasks.py`) to ask for what the report should
actually say instead of "sum invoices": call `reconcile_billing` for the
authoritative total invoiced / total paid / outstanding balance (explicitly
told *not* to hand-sum raw `read_context` rows), use the raw log only for
supporting detail (statuses, dates, late payments), and add a findings
section listing the anomalies `reconcile_billing` returns (reissued
invoices, credit notes, undocumented adjustments) plus anything else notable
in the raw log.

Verified: read the prompt text back after the edit — it names the tool,
tells the agent what not to do (hand-sum), and asks for the reconciled
numbers plus the anomalies section. Ran `ruff check` (clean) and the
existing `pytest` suite (11 passed, no regressions — no new tests yet,
that's step 5).
